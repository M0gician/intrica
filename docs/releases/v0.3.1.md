## English

### Changes

- Native servers support an explicit no-sandbox mode when user namespaces
  are unavailable. Default installations require a working tool sandbox.
- SSH deployment shows the host's isolation availability, lets you select
  the execution mode, and includes that choice in the confirmation.
- Server connection inspection distinguishes enabled, explicitly disabled
  and unavailable tool sandboxes, with separate host capability for SSH.
- Updates preserve the saved mode. Planning checks the release's declared
  capabilities; installation rechecks the archive and saved configuration
  before stopping the existing service.
- The service enforces its configured mode before opening the database.
  An unavailable required sandbox does not trigger an automatic downgrade.

This mode controls native server tools. It does not disable Electron's
browser sandbox or change container isolation, firewall or kernel settings.
There is no tool-schema or database-schema change in this release.

### Desktop installation

Desktop includes Node.js, PostgreSQL and the Web interface. Downloads and
updates need no GitHub account, personal token or GitHub CLI.

**macOS:** open the DMG and drag `Intrica.app` to Applications, or extract
the ZIP and move the app there. Quit Intrica before replacing an existing
copy. **This release is ad-hoc signed and not Apple-notarized.** If blocked,
use **System Settings → Privacy & Security → Open Anyway** after the first
launch attempt. Do not disable Gatekeeper globally.

**Debian/Ubuntu:** run `sudo apt install ./Intrica-0.3.1-linux-amd64.deb`,
then launch `intrica` in your graphical session.

**AppImage:** run `chmod +x Intrica-0.3.1-linux-x86_64.AppImage`, then
`./Intrica-0.3.1-linux-x86_64.AppImage`. If FUSE 2 is unavailable, launch with
`APPIMAGE_EXTRACT_AND_RUN=1 ./Intrica-0.3.1-linux-x86_64.AppImage`.

For manual downloads, compare `shasum -a 256 FILE` (macOS) or
`sha256sum FILE` (Linux) against the exact filename in `SHA256SUMS` above.
Do not install a file whose checksum differs.

Local Desktop starts its server automatically. Add your provider's API
endpoint and model in **Settings → Models**. Model API keys are separate
from Intrica server access tokens. Provider calls may incur charges.

### Native Linux server: choose an execution mode

Use a dedicated non-root Linux x64 account with a systemd user session and
enabled linger. Bash, curl, tar, sha256sum and flock are required. The
default mode also needs working `/usr/bin/bwrap` with unprivileged user
namespaces. An administrator must arrange these prerequisites, including
`loginctl enable-linger SERVER_USER`.

Download the pinned installer and review it before running:

```sh
curl -q --fail --location --proto '=https' --proto-redir '=https' \
  https://github.com/M0gician/intrica/releases/download/v0.3.1/install-server.sh \
  -o install-server.sh
```

Choose **one** command, using the service account without sudo:

```sh
# Require the default tool sandbox.
bash install-server.sh v0.3.1 --sandbox

# Explicitly allow tools to run without OS sandboxing.
bash install-server.sh v0.3.1 --no-sandbox
```

In no-sandbox mode, application permissions remain, but shell and MCP
commands can access all files and network resources available to the service
account. A working directory does not confine them. Use an account without
sudo access or personal credentials. Required mode still permits explicitly
authorized full-host commands through the existing approval path.

Omitting either switch preserves an installed mode; a new installation
defaults to required. The saved setting is `sandbox` in
`~/.config/intrica/server.json`. Keep this configuration private.

```sh
systemctl --user status intrica-server
curl --fail http://127.0.0.1:3001/api/v2/ready
journalctl --user -u intrica-server -n 80
```

New services bind to `127.0.0.1:3001`. In Desktop, open **Settings → Server
connections → Add server**, choose an SSH alias or manually enter host,
username and port, then choose **Deploy Intrica…**. Enter `v0.3.1`, select
**No-sandbox mode** only if intended, prepare and confirm the plan, and
choose **Deploy and save connection**. Return to the list and enable the
connection. Verify SSH host keys and set up key authentication first.

### Updates and other installation paths

Stop active work and back up PostgreSQL, the full state directory and
private configuration before upgrading. Desktop updates its bundled server;
remote services are updated separately under the same account. Keep the
same credentials, state directories and container volumes. Database
migrations cannot be undone by replacing the executable with an older one.

For Docker Compose, use this release's `compose.release.yaml` and copy the
exact `serverImage` value from
[intrica-update.json](https://github.com/M0gician/intrica/releases/download/v0.3.1/intrica-update.json)
into your private `.env`. Pulls need no GitHub login. Bind port 3001 to
loopback for local or SSH access; configure HTTPS before network exposure.

Full instructions for SSH tunnels, Compose, source builds, models and
backups: [English installation guide](https://github.com/M0gician/intrica/blob/v0.3.1/README.md)
and [update safety](https://github.com/M0gician/intrica/blob/v0.3.1/docs/updating.md).

## 简体中文

### 本版变更

- 原生服务器支持显式无沙箱模式，可用于不允许创建用户命名空间的主机。默认安装仍要求可用的工具沙箱。
- SSH 部署显示主机隔离能力，支持选择执行模式，并在确认计划中展示该模式。
- 服务器连接检查区分“沙箱已启用”“无沙箱模式”和“沙箱不可用”，并单独显示 SSH 主机的沙箱能力。
- 升级保留已保存的模式。生成计划时检查版本声明的能力；安装时再次检查安装包和已有配置，再停止原服务。
- 服务在打开数据库前验证执行模式。要求沙箱时，隔离不可用会拒绝启动，不自动降级。

该模式仅控制原生服务器的工具执行，不关闭 Electron 浏览器沙箱，不更改容器隔离、防火墙或内核设置。本版没有修改工具参数或数据库 schema。

### 安装桌面版

桌面版自带 Node.js、PostgreSQL 和 Web 界面。下载与更新无需 GitHub 账号、个人访问令牌或 GitHub CLI。

**macOS：**打开 DMG，将 `Intrica.app` 拖入“应用程序”；也可以解压 ZIP 后移动应用。替换已有应用前先退出 Intrica。**此版本使用临时签名（ad-hoc signing），未经 Apple 公证。** 首次启动被拦截时，打开“系统设置 → 隐私与安全性 → 仍要打开”。不要全局关闭 Gatekeeper。

**Debian/Ubuntu：**运行 `sudo apt install ./Intrica-0.3.1-linux-amd64.deb`，然后在图形会话中启动 `intrica`。

**AppImage：**先运行 `chmod +x Intrica-0.3.1-linux-x86_64.AppImage`，再运行 `./Intrica-0.3.1-linux-x86_64.AppImage`。没有可用的 FUSE 2 时，使用 `APPIMAGE_EXTRACT_AND_RUN=1 ./Intrica-0.3.1-linux-x86_64.AppImage`。

手动下载后，用 macOS 的 `shasum -a 256 FILE` 或 Linux 的 `sha256sum FILE` 计算校验值，与上表 `SHA256SUMS` 中对应文件比较。不一致时不要安装。

本地桌面版自动启动内置服务器。在“设置 → 模型”中配置服务商端点和模型。模型 API 密钥与 Intrica 服务器访问令牌分别管理；模型调用可能产生费用。

### Linux 原生服务器：选择执行模式

使用专用的非 root Linux x64 账号，需要 systemd 用户会话和已启用的 linger，以及 Bash、curl、tar、sha256sum、flock。默认模式还需要支持非特权用户命名空间的 `/usr/bin/bwrap`。管理员负责配置这些条件，包括为服务账号执行 `loginctl enable-linger SERVER_USER`。

下载指定版本的安装器，阅读后再运行：

```sh
curl -q --fail --location --proto '=https' --proto-redir '=https' \
  https://github.com/M0gician/intrica/releases/download/v0.3.1/install-server.sh \
  -o install-server.sh
```

以下命令**二选一**，使用服务账号执行，不加 sudo：

```sh
# 要求默认工具沙箱。
bash install-server.sh v0.3.1 --sandbox

# 明确允许工具在没有操作系统沙箱的情况下执行。
bash install-server.sh v0.3.1 --no-sandbox
```

无沙箱模式仍保留应用权限检查，但 shell 和 MCP 命令可以访问服务账号可用的全部文件和网络资源，工作目录不限制其访问范围。请使用无 sudo 权限且不存放个人凭据的专用账号。要求沙箱的模式仍允许通过现有审批流程明确授权的完整宿主执行。

不传入这两个开关时，升级保留原模式，新安装默认要求沙箱。所选模式保存在 `~/.config/intrica/server.json` 的 `sandbox` 字段中；请勿公开此配置文件。

```sh
systemctl --user status intrica-server
curl --fail http://127.0.0.1:3001/api/v2/ready
journalctl --user -u intrica-server -n 80
```

新服务默认监听 `127.0.0.1:3001`。桌面版打开“设置 → 服务器连接 → 添加服务器”，选择 SSH 别名或手动填写主机、用户名和端口，再选择“部署 Intrica…”。填写 `v0.3.1`；需要时明确勾选“无沙箱模式”，生成并确认计划，点击“部署并保存连接”，返回列表打开连接开关。使用前先验证 SSH 主机密钥并配置密钥认证。

### 更新与其他安装方式

升级前停止任务，备份 PostgreSQL、完整数据目录和私有配置。桌面版更新包含内置服务器；远程服务使用原账号单独更新。保留原凭据、数据目录和容器卷。将程序换回旧版不能撤销数据库迁移。

Docker Compose 使用本版 `compose.release.yaml`，从 [intrica-update.json](https://github.com/M0gician/intrica/releases/download/v0.3.1/intrica-update.json) 复制完整的 `serverImage` 值到私有 `.env`。拉取无需 GitHub 登录。仅从本机或 SSH 访问时将 3001 端口绑定到回环地址；对外提供网络访问前先配置 HTTPS。

SSH 隧道、Compose、源码运行、模型和备份的完整说明见[中文安装指南](https://github.com/M0gician/intrica/blob/v0.3.1/README.zh-CN.md)及[更新安全说明](https://github.com/M0gician/intrica/blob/v0.3.1/docs/updating.md)。
