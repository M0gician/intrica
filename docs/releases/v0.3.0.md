## English

### Included in this release

- Visual workspaces for notes, files, images, PDFs, web pages and tasks.
- Agent teams with explicit permissions, durable tool results and result review.
- Right-side conversation navigation, previews and bookmarks.
- Shared Web/Desktop settings, model discovery, editable shortcuts and SSH deployment.
- Public installation and updates without GitHub accounts, personal tokens or GitHub CLI.

Desktop includes Node.js, PostgreSQL and the Web interface. Linux packages
target x64 glibc systems and are checked on Ubuntu 22.04. Windows, Intel Mac,
Linux arm64 and Alpine/musl packages are not provided. The container image
targets Linux x64. Source is MIT-licensed; dependencies retain their licenses.

### Install Desktop

**macOS:** download the DMG above, open it, and drag `Intrica.app` into
Applications. For ZIP, extract it and move the app to Applications.
Open Intrica there. **This release is ad-hoc signed, not Apple-notarized.**
If macOS blocks the first launch, dismiss the alert and use
**System Settings → Privacy & Security → Open Anyway**, then confirm.
If your device does not offer that option, contact its administrator;
do not disable Gatekeeper globally. Quit an existing app before replacing it.

**Debian/Ubuntu:** run in the directory containing the downloaded DEB:

```sh
sudo apt install ./Intrica-0.3.0-linux-amd64.deb
intrica
```

**AppImage:** run as a regular user in a graphical desktop session:

```sh
chmod +x Intrica-0.3.0-linux-x86_64.AppImage
./Intrica-0.3.0-linux-x86_64.AppImage
```

If FUSE 2 is unavailable:

```sh
APPIMAGE_EXTRACT_AND_RUN=1 ./Intrica-0.3.0-linux-x86_64.AppImage
```

For manual downloads, compare the SHA-256 with the exact filename in
`SHA256SUMS` above. Use `shasum -a 256 FILE` on macOS or `sha256sum FILE`
on Linux, replacing `FILE` with your downloaded package. Do not install a
file whose checksum differs; download it again from this release.

**Optional installer script:** with Bash and curl installed, download:

```sh
curl -q --fail --location --proto '=https' --proto-redir '=https' \
  https://github.com/M0gician/intrica/releases/download/v0.3.0/install.sh \
  -o install.sh
```

Review the script, quit Intrica, then run:

```sh
bash install.sh v0.3.0
```

It verifies the package and installs to `/Applications/Intrica.app`, via
Debian/Ubuntu's `apt-get`, or as `~/.local/bin/intrica` for other Linux x64
systems. Administrator privileges are requested only where needed.
The macOS first-launch approval still applies.

### First launch and models

Local Desktop starts its bundled server automatically; leave the built-in
local connection selected. No server address or access token is required.
Set the interface language in **Settings → General**.

In **Settings → Models**, add your provider's API base URL and API key.
Choose **No API key** only for an endpoint that requires none. Add a model,
select the endpoint's supported protocol, test it, and select it for use.
The editor fetches the model list automatically and supports refresh and
manual model IDs. The mock model makes no real requests; provider calls
may incur charges. Create a canvas, add resources and give an Agent a task.
Review permission requests before granting additional access.

### Native Linux server and SSH

Use a dedicated **non-root Linux x64 account**. The host needs Bash, curl,
`tar`, `sha256sum`, `flock`, a systemd user session, enabled linger and working
`/usr/bin/bwrap` with unprivileged namespaces. An administrator must arrange
these prerequisites, including `loginctl enable-linger SERVER_USER` for the
service account. The installer does not change firewall or namespace policy.

Log in directly as that account and check:

```sh
systemctl --user show-environment
loginctl show-user "$(id -un)" -p Linger --value
/usr/bin/bwrap --unshare-all --die-with-parent --new-session \
  --ro-bind / / --proc /proc --dev /dev /bin/true
```

The linger check must return `yes`; the other checks must succeed.
Download and review the installer:

```sh
curl -q --fail --location --proto '=https' --proto-redir '=https' \
  https://github.com/M0gician/intrica/releases/download/v0.3.0/install-server.sh \
  -o install-server.sh
```

Run it without `sudo`, then verify the service:

```sh
bash install-server.sh v0.3.0
systemctl --user status intrica-server
curl --fail http://127.0.0.1:3001/api/v2/ready
```

The package includes Node.js, PostgreSQL and the Web client. New services
listen on `127.0.0.1:3001` and stay running after logout and reboot.
Configuration is in `~/.config/intrica/server.json`; the default data
directory is `~/.local/share/intrica-server/state`. Read `accessToken` from
the configuration privately for manual connections. Never publish the
configuration or use its database password as the access token.
Use `journalctl --user -u intrica-server -n 80` for service logs.

**From Desktop:** first configure SSH key authentication and verify the
host fingerprint with its administrator. Load encrypted keys into your
SSH agent; Intrica uses non-interactive SSH and cannot prompt for passwords.
Open **Settings → Server connections → Add server**, choose an SSH alias,
or use **Add a server manually…** for host, username and port.
For a new service, choose **Deploy Intrica… → Check SSH host**, enter
`v0.3.0`, then **Prepare deployment plan**. Review the account, host, version
and data location, confirm, and choose **Deploy and save connection**.
Return to the list and enable the connection. For an installed service under
the same account, choose **Add** directly. Desktop manages the tunnel and
retrieves the service token over SSH.

**From a browser:** on your local computer, replace `intrica-host` with your
SSH alias and keep this tunnel running:

```sh
ssh -N -L 127.0.0.1:3301:127.0.0.1:3001 intrica-host
```

Open `http://127.0.0.1:3301` and enter the Intrica access token. For an
existing HTTPS service, use Desktop's manual **HTTP / HTTPS** connection
with its address and token. Intrica tokens grant owner access and are
separate from model API keys. Use HTTPS or SSH across untrusted networks.

### Docker Compose

On a Linux x64 host with Docker Engine and Compose v2, create a persistent
deployment directory and download the release file:

```sh
mkdir intrica-deployment
cd intrica-deployment
curl -q --fail --location --proto '=https' --proto-redir '=https' \
  https://github.com/M0gician/intrica/releases/download/v0.3.0/compose.release.yaml \
  -o compose.release.yaml
openssl rand -hex 32
```

Create `.env` with your editor. Replace the placeholder with the generated
random value and keep it private. This is the v0.3.0 image digest from
[intrica-update.json](https://github.com/M0gician/intrica/releases/download/v0.3.0/intrica-update.json):

```ini
INTRICA_IMAGE=ghcr.io/m0gician/intrica@sha256:75dc1139534bb1cfe742d42c2b6786eb4f58ed1b6048a951414026134818b4be
INTRICA_ACCESS_TOKEN=REPLACE_WITH_YOUR_RANDOM_VALUE
```

Before starting, change the downloaded file's `3001:3001` port mapping to
`127.0.0.1:3001:3001` for host-local or SSH-tunnel access. The original
mapping exposes port 3001 on all host interfaces. For network access,
configure HTTPS and network access restrictions first.

```sh
chmod 600 .env
docker compose -f compose.release.yaml up -d --wait
docker compose -f compose.release.yaml ps
```

Open `http://127.0.0.1:3001` on the host, or use the SSH tunnel above, and
sign in with `INTRICA_ACCESS_TOKEN`. Pulling needs no `docker login`.
Preserve `.env`, the deployment directory, `pgdata` and `intrica-data`.
`docker compose down -v` deletes the workspace volumes.

### Run from source

Install Git, Node.js 24.18.0 and pnpm 11.20.0:

```sh
git clone --branch v0.3.0 --depth 1 https://github.com/M0gician/intrica.git
cd intrica
pnpm install --frozen-lockfile
pnpm --filter @intrica/desktop run prepare:app
pnpm --filter @intrica/desktop exec electron . --user-data-dir="$(pwd)/.data/desktop-dev"
```

These commands use a separate desktop development profile in the checkout.
For a browser-only workspace, run `HOST=127.0.0.1 pnpm web` after installing
dependencies, then open `http://127.0.0.1:3001`. Ctrl+C stops the server.
Without `HOST`, `pnpm web` listens on all interfaces and prints a private
access-token URL. Browser development uses `.data/web` by default.

### Updates, backups and limits

Use **Settings → Version & updates** to download and verify Desktop updates.
Stop active work, back up, quit the app, then open the installer and replace
the application. Remote services are updated separately, using the same
account, configuration and data directories. For Compose, keep the existing
project and volumes, change `INTRICA_IMAGE` to the selected release digest,
then run `docker compose -f compose.release.yaml pull intrica` and
`docker compose -f compose.release.yaml up -d --no-deps --wait intrica`.

Before any upgrade, stop application writers and back up PostgreSQL and the
complete workspace. Desktop data is in `~/Library/Application Support/Intrica`
on macOS or `${XDG_CONFIG_HOME:-$HOME/.config}/Intrica` on Linux. Native
services also need a backup of their configured state directory and
`~/.config/intrica/server.json`; containers need both data volumes and `.env`.

Schema 8 and 9 migrate to schema 10. Affected conversations pause for
result verification and explicit continuation; unknown side effects are
not automatically retried. Downgrading the executable cannot undo a database
migration. Intrica supports individuals and trusted teams, without separate
tenant accounts. Read [updates and recovery](https://github.com/M0gician/intrica/blob/v0.3.0/docs/updating.md)
and [self hosting](https://github.com/M0gician/intrica/blob/v0.3.0/docs/self-hosting.md).

### 首次启动与模型配置

本地桌面版自动启动内置服务器，保持选中内置本地连接即可，无需填写服务器地址或访问令牌。界面语言在“设置 → 通用”中选择。

在“设置 → 模型”中填写服务商提供的 API 基础地址和 API 密钥。仅在端点不要求密钥时勾选“无需 API 密钥”。添加模型，选择端点支持的协议，测试后选择使用。编辑器会自动获取模型列表，也支持刷新或手动输入模型 ID。内置模拟模型不会发送真实请求；调用服务商模型可能产生费用。随后新建画布、添加资料并给 Agent 分配任务；授予额外权限前先审查申请。

### Linux 原生服务器与 SSH

使用专用的**非 root Linux x64 账号**。主机需要 Bash、curl、`tar`、`sha256sum`、`flock`、systemd 用户会话、已启用的 linger，以及支持非特权用户命名空间的 `/usr/bin/bwrap`。管理员负责配置这些条件，并为服务账号执行 `loginctl enable-linger SERVER_USER`，其中 `SERVER_USER` 为实际用户名。安装器不会修改防火墙或命名空间策略。

直接以该账号登录，检查：

```sh
systemctl --user show-environment
loginctl show-user "$(id -un)" -p Linger --value
/usr/bin/bwrap --unshare-all --die-with-parent --new-session \
  --ro-bind / / --proc /proc --dev /dev /bin/true
```

linger 应返回 `yes`，另外两项应成功。下载并阅读安装器：

```sh
curl -q --fail --location --proto '=https' --proto-redir '=https' \
  https://github.com/M0gician/intrica/releases/download/v0.3.0/install-server.sh \
  -o install-server.sh
```

不加 `sudo` 运行安装器，再检查服务：

```sh
bash install-server.sh v0.3.0
systemctl --user status intrica-server
curl --fail http://127.0.0.1:3001/api/v2/ready
```

原生包自带 Node.js、PostgreSQL 和 Web 界面。新服务默认监听 `127.0.0.1:3001`，退出登录后继续运行，并随主机启动。配置保存在 `~/.config/intrica/server.json`，默认数据目录为 `~/.local/share/intrica-server/state`。手动连接时私下读取配置中的 `accessToken`；不要公开配置文件，也不要将数据库密码用作访问令牌。日志使用 `journalctl --user -u intrica-server -n 80` 查看。

**使用桌面版：**先配置 SSH 密钥认证，并与管理员核对主机指纹。加密密钥应先加载到 SSH agent；Intrica 使用非交互 SSH，无法弹出密码输入框。打开“设置 → 服务器连接 → 添加服务器”，选择 SSH 别名，或用“手动添加服务器…”填写主机、用户名和端口。新服务选择“部署 Intrica… → 检查 SSH 主机”，填写 `v0.3.0`，点击“生成部署计划”。核对账号、主机、版本和数据位置，确认后点击“部署并保存连接”，再返回列表打开连接开关。同一账号下已安装服务时，直接选择“添加”。桌面版管理隧道，并通过 SSH 获取服务访问令牌。

**使用浏览器：**在本地电脑运行以下命令，将 `intrica-host` 替换为自己的 SSH 别名，并保持隧道运行：

```sh
ssh -N -L 127.0.0.1:3301:127.0.0.1:3001 intrica-host
```

打开 `http://127.0.0.1:3301`，填写 Intrica 访问令牌。已有 HTTPS 服务可在桌面版手动选择“HTTP / HTTPS”连接并填写地址和令牌。Intrica 令牌授予所有者权限，与模型 API 密钥分别管理。不可信网络中使用 HTTPS 或 SSH。


### 更新、备份与限制

在“设置 → 版本与更新”中下载并校验桌面更新。停止任务、备份并退出应用，再打开安装包替换应用。远程服务单独更新，并保持原账号、配置及数据目录。Compose 保留原项目和数据卷，将 `INTRICA_IMAGE` 改为目标版本摘要，然后执行 `docker compose -f compose.release.yaml pull intrica` 和 `docker compose -f compose.release.yaml up -d --no-deps --wait intrica`。

任何升级前都应停止应用写入进程，备份 PostgreSQL 和完整工作区。桌面版数据位于 macOS 的 `~/Library/Application Support/Intrica`，或 Linux 的 `${XDG_CONFIG_HOME:-$HOME/.config}/Intrica`。原生服务还需备份配置指定的数据目录及 `~/.config/intrica/server.json`；容器需备份两个数据卷及 `.env`。

schema 8 和 9 会迁移到 schema 10。受影响会话暂停，等待核实结果并明确继续；未知副作用不会自动重试。更换回旧程序不能撤销数据库迁移。Intrica 面向个人和互相信任的团队，不提供独立租户账号。升级前阅读[更新与恢复指南](https://github.com/M0gician/intrica/blob/v0.3.0/docs/updating.md)及[自托管指南](https://github.com/M0gician/intrica/blob/v0.3.0/docs/self-hosting.md)。
