# Intrica v0.5.5

## English

This maintenance release improves connection recovery, stream consistency and
query efficiency, and removes redundant implementation and test code. Desktop
and Server are **0.5.5**.

### Changes

- Keep valid saved desktop connections when another entry is malformed. Treat
  only missing identity or update-journal files as absent; retain corrupt,
  unsupported or unreadable files and report the failure explicitly.
- Share assistant message updates and stream recovery. Clear stale state after
  reset, coalesce duplicate recovery requests, and stop recovery after a view
  closes. Application sessions and browser fixtures receive explicit connection
  and store providers.
- Reuse permission lookups within a single comparison and batch message
  references, progress evidence and archive searches. Derive public request
  types from their validation schemas while preserving supported optional values.
- Remove unused helpers, duplicate contracts, unused styles and redundant
  fallback paths. Keep authorization, unknown-outcome barriers and compatible
  stream formats.
- Check actual database graph output and frozen historical upgrade schemas.
  Correct absent optional metadata fields, simplify fresh schema definitions,
  and keep historical database contents intact.
- Separate large benchmarks and visual experiments from ordinary regression
  tests. Run safety mutations against an isolated shared PostgreSQL cluster
  with byte-for-byte restoration, cover standalone browser fixtures in CI, and
  wait for default-model persistence before checking its saved state.

The cleanup includes PRs #41–#45. Its verification and retention decisions are
recorded in the [implementation audit](../development/cleanup-audit-2026-10-15.md).

### Upgrade

Database **schema 18** and tool **schema 7** are unchanged from 0.5.4. Stop active
work and back up the complete database and data directory before updating.
Update Desktop and any separately deployed Server, then reconnect clients.
Fresh databases no longer create the unused `inbox_reviews` table; existing
tables and historical records are retained. See [updates and recovery](../updating.md)
for older-version migrations and recovery requirements.

**macOS uses ad-hoc signing and is not notarized by Apple.** Quit Intrica and
manually replace the app in Applications. If startup is blocked, use System
Settings → Privacy & Security → Open Anyway.

Downloads include macOS Apple Silicon DMG/ZIP, Linux x64 DEB/AppImage, the Linux
x64 native server and a server container. `intrica-update.json` and `SHA256SUMS`
provide the complete inventory, image digest and file checksums.

## 简体中文

本维护版本改进连接恢复、流式消息状态和查询效率，并清理冗余实现与测试。
桌面端与服务端版本统一为 **0.5.5**。

### 改进内容

- 某条连接记录格式错误时，继续恢复其他有效连接。身份文件和更新日志仅在不存在时按缺失处理；文件损坏、版本不支持或无法读取时保留原文件，并明确报告错误。
- 统一助手消息更新与流恢复。重置时清除旧消息，合并重复恢复请求，视图关闭后停止恢复。应用会话与独立浏览器测试显式提供连接和状态服务。
- 在单次比较中复用权限查询，批量处理消息引用、进度证据和归档搜索。从校验 schema 派生公开请求类型，保留已有可选值的兼容性。
- 删除无引用的辅助函数、重复契约、无用样式及冗余回退路径，保留权限校验、未知结果阻塞规则和兼容的流格式。
- 校验实际数据库图输出和固定的历史升级 schema，修正缺失的可选元数据字段，简化新数据库定义并保留历史数据。
- 将大型基准与视觉实验从常规回归中分离；安全消融使用隔离的共享 PostgreSQL 集群，逐字节确认代码恢复。独立浏览器测试纳入 CI，默认模型验收等待保存完成后再读取结果。

本次清理包含 PR #41–#45，逐项验证和必要实现的保留依据见
[实现审计记录](../development/cleanup-audit-2026-10-15.md)。

### 升级说明

数据库 **schema 18** 和工具 **schema 7** 与 0.5.4 保持一致。升级前停止正在执行的工作，
备份完整数据库和数据目录。更新桌面端以及单独部署的服务端，然后重新连接客户端。
新数据库不再创建未使用的 `inbox_reviews` 表；已有表及历史记录会保留。
从更早版本升级时的迁移和恢复要求见[更新与恢复](../updating.md)。

**macOS 使用临时签名，未经 Apple 公证，需要手动安装。** 请退出 Intrica，替换“应用程序”中的旧版。
若 macOS 拦截启动，在“系统设置 → 隐私与安全性”中选择“仍要打开”。

发布产物包含 macOS Apple Silicon 和 Linux x64 桌面安装包、Linux x64 原生服务包及服务端容器。
完整文件清单、镜像摘要和文件校验值见 `intrica-update.json` 与 `SHA256SUMS`。
