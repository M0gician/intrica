# 运行可靠性实施计划

状态：A–E 的代码已落地，并通过本机受控验证；真实模型及跨平台安装包验收待进行。基线为 v0.4.0（`6a900f3`），工作分支为 `codex/runtime-reliability-redesign`。设计依据见[运行可靠性重构设计](../architecture/runtime-reliability-redesign.md)。本次验证仅使用隔离数据目录，未操作 m4-dev 的现有画布或发布新版本。

先建立真实指令与摘要的边界，再联调统一进展复核及提醒，随后接入模型调度和文件工具契约。每一阶段交付完整行为及回归证据，最终统一切换版本。

## 实施阶段

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| A 指令和上下文 | 现有消息来源引用、结构化摘要快照、唯一摘要及 checkpoint 恢复 | 错误摘要不能覆盖真实要求，失败及并发替换保留有效上下文 |
| B 进展复核与提醒 | 扁平 review_progress、独立消息操作、增量信箱及普通提醒 | 完成/继续/等待/阻塞语义准确，普通提醒不取消推理，已读不使全部确认失效 |
| C 模型调度 | 共享额度组、持久请求队列、分类重试及安全状态 | 14 个成员及摘要共享容量 10 时公平排队，429 不要求重发任务 |
| D 文件和工具 | 扁平 read、流式文本、来源游标、统一效果回执 | 大于 1MiB 文件可完整续读，错误准确表达效果 |
| E 产品切换 | 双语 UI、系统提示、契约版本、历史数据迁移及端到端验收 | 所有入口使用新契约，现有发布、权限和恢复检查通过 |

模型调度可先在独立模块完成，但普通推理和摘要必须同时接入才算阶段 C 完成。任务结束检查和复核必须联调，避免各自通过却仍把“无待回复消息”当成“原任务完成”。

| 位置 | 实际职责 |
| --- | --- |

| `modules/context/summary-contract.ts`、`summary.ts` | 结构化摘要、冻结来源、统一模型请求及校验 |
| `modules/work/progress/sources.ts` | 读取真实用户和委派来源，恢复缺失原文，保留现有输入位置 |
| `modules/work/progress/review.ts`、`completion.ts` | 四种进展结论、自然结束检查和有界提示 |

| `modules/work/progress/execution-state.ts`、`deliveries.ts`、`dependencies.ts` | 工具结果核实、实际交付关联、真实唤醒依赖 |

| `modules/work/tools/read.ts` | 扁平 read、游标持久化及每页重新授权 |

| `db/migrations/0017-runtime-redesign.sql` | schema 17 一次切换和旧未执行调用封存 |

仓储实现按所属模块分开。适配器只处理传输或文件系统事实，业务状态通过窄接口交给领域模块。现有 access、graph 和通用 execution 继续复用。

源文件以一个主要变更原因为单位，通常控制在 150–350 行。接近 400 行时检查是否同时承担校验、存储、调度和展示；超过 600 行的新增或显著扩展实现必须拆分职责，不新增上千行核心文件。不能用压缩代码行、空包装或大量跳转规避要求。测试按功能拆分共享夹具，避免再形成巨型回归文件。

静态边界检查已增加 context、model-runtime 与业务模块的依赖方向约束。现有规则同时检查禁止导入和模块环；实际恢复行为通过集成测试检查。组合入口不含 SQL、提供者解析或文件读写算法；HTTP 仅委托应用服务。

## 持久记录和事务边界

| 数据 | 所有者 | 关键约束 |
| --- | --- | --- |
| 真实指令来源 | work/progress | 引用已有用户消息和获准委派，按顺序提供原文，不复制成独立任务树 |
| 进展复核与交付关联 | work/progress | 保存 outcome、reason、剩余事项和证据；阶段成果不能自动视为完成 |
| 摘要快照及来源清单 | context | 固定来源、保留上一有效版本、迟到结果不能覆盖新状态 |
| 模型请求和网络尝试 | model-runtime | 同一请求沿用身份，重试重新核对任务和上下文 |
| 额度租约及冷却 | model-runtime | 多 Worker 共用额度，失效租约不能继续派发 |
| 信箱读取边界、短引用和决定 | work/progress | ref 绑定作用域，独立扁平操作幂等，完成项不使无关决定失效 |
| 读取游标 | work/tools/read | 绑定主体、目标、版本与期限，每页重新授权 |
| 工具效果回执 | execution | 已提交效果优先，unknown 不能变成自动重试 |

后续执行、最终交付、进展复核和运行结束在相同的版本及租约检查下提交。外部提供者请求和文件写入不能假装成为数据库事务的一部分；它们使用持久派发记录、结果回执和可确认的恢复规则。

不创建第二份各自演化的权限或消息状态库。派生状态使用单一投影；持久重复字段必须有明确的写入事务和一致性测试。

## 数据和协议切换

新服务端、Web、桌面端、数据库 schema 17、工具 schema 6 和系统提示作为同一版本发布。旧 `read.target`、旧 review_inbox/wait_for_message 双工具、确认数组及 token 协议和旧 `executed` 字段不提供运行时别名；文档与示例只展示新协议。

历史可读性与旧操作继续执行分开处理。升级保留消息、产物、既有工具回执和审计证据。旧 schema 下未派发的模型工具调用封存并标注需重新规划；已经提交的操作仍返回原回执，结果未知的操作保持阻塞。旧审批不能被转换成授权更宽的新操作。

真实用户消息及现有委派关系用于记录指令来源引用；不创建完整 tasks 或父子任务管理系统。无法确定的来源保留为待核对记录，不能把 assistant 摘要当作用户原文。旧消息仍按原事实显示，协议切换不补发消息或重新执行任务。

升级前停止新准入，在安全边界停止执行并备份数据库和数据目录；随后一次事务迁移并检查版本，再启动匹配客户端。旧服务端拒绝新数据库版本。回滚使用匹配备份，不启动旧代码读取已迁移数据库。迁移验收在独立副本完成，不操作用户正在运行的画布。

## 验收矩阵

所有检查以实际请求、持久状态、产物字节和执行次数为断言目标。模型测试使用受控响应和真实 PostgreSQL、HTTP、文件系统；真实模型行为另行记录。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 摘要缺少必需字段、来源范围错误，或只返回一句“我会总结” | 候选被拒绝，原 checkpoint 可用，原用户目标仍进入后继请求 |
| A02 | 摘要伪造用户取消、授权或已完成 | 真实指令和权限不变化；后继请求保持实际目标及约束 |
| A03 | 两个会话并发压缩，返回顺序交错 | 输入范围、输出和提交身份各自匹配，不能串用快照 |
| A04 | 压缩期间新指令、撤权、取消或接管 | 下一请求使用当前指令边界；旧 Worker 不能提交失效结果 |
| A05 | 阶段交付且存在后续步骤 | review_progress 选择 continue 或真实等待，不因信箱为空视为整个要求完成 |
| A06 | completed/blocked、用户停止、预算耗尽及未知副作用 | 分别保存正确结论及运行状态，不强制复核或无限恢复；结果不重发 |
| C01 | 14 个成员及摘要请求共享容量 10 | 按额度组排队；提供者可观察并发不超过配置值，所有会话获得执行机会 |
| C02 | 429 并发已满与引擎过载 | 错误分类准确，按策略等待，在原任务上恢复，不新增重复任务消息 |
| C03 | Retry-After、配置修复及重试窗口用尽 | 不提前请求；修复后恢复；窗口用尽可见且保留工作 |
| C04 | 多 Worker 争抢、崩溃及迟到响应 | 租约和派发唯一，已执行工具次数不增加 |
| C05 | 通知、状态工具、UI 和诊断查询 | 同一故障显示一致原因，输出没有密钥或私人请求正文 |
| B01 | 0.56 秒内多条普通超时提醒 | 合并或排队，正在进行的模型请求不被取消 |
| B02 | 等待者提醒、显式加急和权限撤销 | 各自触发正确唤醒或中断，暂停和权限仍有效 |
| B03 | read_inbox 后对方读完无需回复的发信 | 已解决项自动移除，其余确认继续有效 |
| B04 | 新请求或依赖回复与确认竞争 | 新增责任进入增量检查；不能漏读后直接结束 |
| B05 | 81 项及更大信箱、失败重试和重启 | 分页与独立消息决定保留进度，最终 review_progress 不要求复制全部 UUID 或回传 token |
| B06 | 短 ref 被用于其他会话，或事项已不再待处理 | 不修改无权或无待办的消息；幂等重试返回原处理结果 |
| D01 | 1,192,073 字节及更大的 UTF-8 文件 | 首次读取成功，沿游标重建的字节与原文件一致，内存和返回量有界 |
| D02 | Unicode 边界、超长行和远距离定位 | 不丢字、不重复、不把扫描未完成当作 EOF |
| D03 | 游标期间覆盖、替换、撤权及符号链接变化 | 检出来源变化或拒绝，不能读取其他目标或取得新权限 |
| D04 | 目录 auto/text 与图片、PDF、节点、Skill | 正确选择结果类型，模式和索引含义一致 |
| D05 | 参数错误、匹配失败、部分写入和未知结果 | 状态、阶段和效果准确；无效果失败前后目标哈希不变 |
| D06 | 完成效果后取消，恢复或网络响应失败 | 返回原持久回执，不能把已完成效果重跑 |
| E01 | read/write/admin/owner 与中英文 | 权限、提示词、参数和状态文案一致，非管理员看不到管理操作教程 |
| E02 | 320px/480px 会话、键盘和悬浮 | 状态图标位置稳定，时间和身份行为保留，无横向溢出 |
| E03 | 全量构建及实际安装包 | 模块依赖、类型、翻译、已有功能、Web/Electron 矩阵通过 |

并发和重试测试用明确同步屏障与可控时钟构造时序，不用随机等待碰运气。来源校验不能只测试 hash 相等，还要测试来源正确却语义错误时，真实要求和权限仍不受摘要影响。

## 集成运行和完成标准

用独立画布重建“协调者与 13 名成员阅读一个有完整清单的项目”的场景，加入容量 10、引擎过载、无关摘要、已读回执竞争、81 项复核及大文件。验证任务持续推进、阶段成果保留、输入没有丢失、工具效果不重复，最后由明确结果结束。

负载测试报告队列等待、恢复时间、模型中断次数、复核请求体大小、额外模型请求和文件读取峰值内存。目标包括普通提醒导致的中断为 0、无需回复的已读变化导致的全量复核重做为 0，以及大信箱确认负担随每页待决事项而非全部历史增长。

真实模型复测使用独立数据目录和测试资料，记录模型配置、摘要有效性、目标保持、协作分工与最终交付。受控协议通过不替代真实任务质量评估，也不证明上游不会返回异常内容。

每阶段只在对应行为和故障检查通过后完成。最终发版还需现有构建、类型、翻译、模块边界、功能、浏览器和安装包检查。设计完成不等于这些验证已通过。
