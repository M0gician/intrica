## 行为变化

| 范围 | 当前实现 | 关键约束 |
| --- | --- | --- |
| 消息可见性 | 协作收发消息显示未读、已读、等待回复及已回复；广播提供人数汇总和逐个接收者状态 | 已读表示进入持久模型上下文，不表示业务任务完成 |
| 加急 | 原消息和关联提醒显示琥珀色背景、边框与文字标记；区分加急中和已优先送达；刷新后保持 | 检查通信权限、暂停状态和接收者 30 秒冷却；已派发工具保持原回执 |
| 超时提醒 | 所有成员消息都有送达记录；默认 60 秒未读提醒，可选 120 秒预期回复；同批同发送者和原始任务的提醒合并 | 记录版本与已通知条件，抑制重复和失效提醒；原始激活预算保持有效 |
| 继续等待 | `update_message` 延后提醒，保留原始期限 | 停止跟踪保留真实已读状态，仍可收到迟到回复 |
| 等待与结束 | `review_inbox` 分为 inspect、confirm，逐项提交处理决定；结束时也检查未完成协作事项 | 依赖回复用 wait；不影响当前任务的发信用 background 并说明原因；检查过期必须重做 |
| 防止反复检查 | 相同信箱快照最多发出两次结束检查 hook，随后进入可见的 inbox_review 等待 | 没有待处理协作投递的普通会话直接结束 |
| 自动协作 | 新建 Agent 默认响应资源；招募时继承管理者配置；独立持久化暂停状态 | 暂停保留协作信箱和跟踪，阻止消息、资源与定时任务自动启动；用户明确恢复后继续 |
| 资源变化 | 合并受影响资源，10 秒稳定期，最长等待 30 秒；通知带当前获准资源的 ID、版本和快照 hash | 过滤当前权限、保持自修改排除和激活限制 |
| 工作目录 | 文件浏览器默认画布根目录，提供共享目录和成员目录入口 | 终端默认共享目录；导航根目录不构成 Agent 执行授权 |

普通协作消息继续排队进入上下文。未读超时会提醒发送者，由发送者决定等待或加急；
普通消息本身不会无条件打断接收者的推理。

## 画布 4 复核问题的处理

依据 [2026-10-12 复核报告](canvas4-current-run-review-20261012.md)：

- 使用 `deliveryId` 和 `replyTo:{to:"reply",id}` 定位回复，HTTP 追踪字段使用 `traceId`。
  缺少确认字段会返回具体错误，不能静默退回查询。
- `read` 对发布节点的固定字节读取 GIF 帧、时长、循环信息和 hash；可变源路径单独
  标为 `sourcePath`。获得快照权限不再自动获得源路径的读取权限。
- 错误诊断依据 discriminator 选择对应 schema 分支，并保留根级字段约束。
  `access:file` 只允许 `execution:none`，错误直接说明正确字段组合。
- Python 使用实际解释器，绕过 macOS 系统入口的 xcrun 缓存写入；依赖目录按工作区
  隔离，能力发现返回 Pillow 目录是否存在和局部安装方式。
- 浏览器能力返回实际可执行路径、隔离条件、启动参数和临时 profile 路径；动画检查
  建议使用持续 CDP 会话与实际时间采样。私有 RPC 路径的沙箱拒绝规则保持有效。

`report_result` 的移除、同管理者成员之间的通信、持久权限与单次审批的区分，
以及此前的下载、节点正文拖动和 HTML 预览修复，保留在本轮基础提交中并参与回归。

## 模块边界

`message-hooks.ts` 只负责组合，消息投递、回执、提醒、操作、复核和结束检查分别位于
`modules/work/messaging/`。`conversations.ts` 的运行循环、检查点和结束流程拆到
`conversation-runtime/`；两个原入口分别约 70 行和 292 行，运行循环约 559 行。
HTTP 层仅委托服务，执行层不依赖协作或图模块。共享回执和复核类型位于 contracts。

数据库版本为 15，工具版本为 4。迁移、新建数据库及新工具回执的默认版本一致。
