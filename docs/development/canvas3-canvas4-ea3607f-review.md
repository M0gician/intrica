# 画布 3 和画布 4 的实现复核与改进

本次复核以 `ea3607fe5a049162cd1bbccd784b9b8623a11a40` 为唯一代码基线。
实现位于 `codex/message-hooks-ui-repair` 分支；未采用 `e20701c` 的改动。
原始画布、会话和产物只读保留，验证使用独立数据库和临时工作目录。

画布 3 有 4 个会话、174 条消息、75 次工具调用和 70 次模型请求；画布 4 有
4 个会话、341 条消息、175 次工具调用和 85 次模型请求。画布 4 的四次已记录
工具失败包括一次 GIF 的 `frame=0` 调用和三次对已 `satisfied` 申请的审查。
GIF 的自动读取本来就可返回图像，失败的是节点读取中的显式帧参数。
两画布的 9 份文件快照哈希正确，没有发现孤立审批或结果未知的工具调用。

## 逐项问题与实现

| 用户要求 | 基线问题及证据 | 当前改进 |
| --- | --- | --- |
| 1 回复预期和超时提醒 | 发信没有回复期限和持久跟踪状态，运行结束也不能证明请求已答复 | `expectReply`、`replyWithinSeconds`，逐个接收者保存请求；一次超时通知，允许等待、加急或取消跟踪 |
| 2 等待前复核信箱 | `wait_for_message({})` 可以直接进入等待，缺少收发义务检查 | `review_inbox` 返回检查凭据，完整答复或跟踪后产生确认凭据；`confirmed:true` 和有效 `reviewToken` 才能等待 |
| 3 合并结果提交 | `report_result` 与发信分开，根 Agent 没有管理者时容易误读零接收者回执 | 结果统一通过 `send_message` 的 `kind:"result"`；根 Agent 交付给 `user`，成员交付给 `manager` 或原请求；旧工具停用 |
| 4 发信语法 | 嵌套 target 容易被传成 JSON 字符串；基线可复现不准确的参数错误 | 扁平 `to/id/ids/message`，明确示例、默认值和字段组合检查；接收者去重，广播范围冻结 |
| 5 工具错误 | schema 校验失败的调用没有工具记录，只有笼统错误文本 | 校验前保存回执；返回错误码、字段路径、预期类型、实际类型和修正动作；原文消息不回显 |
| 6 同管理员成员互通 | 共同管理员还必须覆盖双方文件资源，私有授权会造成通信审批 | 团队通信按管理链判断；成员可发现并直接联系同团队成员，文件及私有会话仍独立授权 |
| 7 沙箱及能力可用性 | Electron 清理后的 PATH 找不到 node；Chrome 读取运行框架被拒绝；画布 3 的 18 次 bash 有 12 次使用 fullHost | 提供实际 Node 运行路径和工作区命令；读取浏览器程序分发目录，补充受限进程、IPC 和共享内存条件，阻断宿主 RPC 套接字绕过文件边界的通道；实际受限 Chromium 执行脚本、网络访问及 WebGL |
| 8 申请和审批流程 | 画布 4 曾出现 6 次初始读取申请、3 次重复持久授权申请及对已满足申请的审查 | 相同未结持久申请返回原请求 ID；旧版本审查返回当前状态和下一步；保留权限范围、版本和原调用绑定 |
| 9 会话下载链接 | Web 路径先校验再直接导航下载 URL，会脱离认证 transport；Electron 的 HTTP 错误缺少具体原因 | Web 经认证连接获取文件字节再保存；保留会话来源与快照权限检查，下载显示服务器具体错误；会话引用与原始 GIF 分别验证 |
| 10 正文拖拽 | 普通文本和文件正文没有调用已有拖动处理器 | 非 Agent 节点的正文非交互区域可拖动，按钮、链接及待办触摸滚动继续工作 |
| 11 HTML 预览 | 原预览器删掉 script，iframe 不允许脚本；画布 3 使用 Three.js 和 WebGL | 浏览器侧栏打开授权产物，脚本在独立来源 iframe 中执行；原始 HTML 的渲染和暂停、继续交互验证通过 |

`06dba02c712e969701d5258311a8af5d8012a99f2f3a2a00319fe339ae16c326`。

## 消息发送回复与等待流程

```json
{"to":"agent","id":"成员ID","message":"请核对产物","expectReply":true,"replyWithinSeconds":120}
{"to":"request","id":"来信requestId","kind":"result","message":"已核对","fileIds":["发布快照节点ID"]}
```

消息投递、输入进入模型上下文、运行结束、收到回复和任务验收分别记录。
回复时复制来信的 `replyTo`，使回复关闭正确请求；向管理者独立汇报结果不会
自动猜测它对应哪一条请求。发送回执和信箱复核均返回请求 ID 与期限。

`review_inbox({})` 提供收到和发出的未结请求、未复核消息、`reviewKey` 和分页
游标。模型按需答复后重新读取信箱，提交 `reviewKey`、`handledMessageIds` 与
`trackRequestIds`。服务端覆盖检查通过后返回 `reviewToken`。新的消息、回复、
期限通知或跟踪动作使确认失效。服务端检查记录覆盖和版本，答复质量由模型判断。

超时通知保存已读证据及接收者运行状态。同一请求版本仅通知一次。继续等待
延长期限；加急携带原请求和回复地址，30 秒内限制对同一接收者重复加急。
停止发送者会取消其未结跟踪；停止的接收者需恢复后才能加急。已开始执行的
工具保留原回执，通知不会重放操作。升级暂停和结果未知的上下文保留原阻塞条件。

## 申请与审批的整体方案

1. 先判断是否已有权限，或是否属于同一管理员的通信团队。已允许的操作直接
   执行；通信许可与文件、节点、私有会话及宿主命令权限分别判断。
2. 对需要新增权限的操作规范化路径、角色及资源范围，在事务中冻结执行参数、
   管理链和权限依据。申请绑定原工具调用，批准不能变成其他调用的通用凭证。
3. 相同未结持久申请复用其跟踪入口，返回原 requestId，避免重复申请和审批通知。
   不同资源、不同执行级别和不同冻结命令保留独立申请。
4. 指定审查者只审查当前 pending 版本及自身有权授予的范围。范围不足、审查者
   不可用或审查超时按现有管理链向上转交。仅用户可授予管理员角色。
5. 决定前重新校验版本、目标、管理链、授权依据及停止状态。权限已满足时记为
   satisfied，不编造批准者；旧通知需要先刷新，不能再次审查已结束的申请。
6. 批准后继续原调用，执行前再校验当前依据。拒绝、过期、取消、目标变化或
   结果未知保留独立状态与明确下一步。拒绝备注与发给申请者的说明分开保存。
7. 后续提高审批页对“权限已获得”“原调用等待调度”“原调用已执行”的区分，
   增加路由及执行延迟指标，按状态定位问题，避免把审批完成当成业务完成。

## Codex 沙箱参考与实现范围

参考 2026-10-12 检查到的公开 Codex 提交
`6e5f665feb9b71e1500a5721036fbdb8e871f4b0`，主要采用运行平台的受限读取、
同沙箱进程信号、系统基础 IPC 和独立临时目录思路。
[官方沙箱文档](https://developers.openai.com/codex/sandboxing)与
[固定提交的实现](https://github.com/openai/codex/tree/6e5f665feb9b71e1500a5721036fbdb8e871f4b0/codex-rs/sandboxing/src)
可交叉核对。

Intrica 保留已有宿主网络策略及单独的宿主执行授权。能力发现返回实际 Node
路径、Electron Node 调用方式和可读浏览器分发目录。Agent 使用自身工作区的
HOME、TMPDIR、XDG 配置与缓存目录。macOS 对浏览器程序框架允许读取和执行映射，
对 Chromium 进程间 Mach 端口提供有限规则；没有放开用户浏览器资料、Keychain、
服务端 secrets、数据库和宿主 RPC 目录。独立服务复现确认：基线网络放行还允许受限进程连接宿主 RPC，故新增对私有目录内 Unix 套接字的网络拒绝规则；直接路径、符号链接和硬链接测试均不能访问宿主服务，同时正常网络和 WebGL 保持可用。Linux 补充只读浏览器分发目录和独立
`/dev/shm`，本次本机运行验证覆盖 macOS，Linux 仍需对应平台执行验证。

内置网页浏览器与产物预览使用各自隔离方式。HTML 产物可以运行脚本、Three.js
和 WebGL，同时不含同源、表单、弹窗和顶层导航能力。远程模块需要满足 CORS；
本地图片通过文件来源权限解析。任意本地 HTML 相对模块和外部页面导航仍应由
后续受限文件服务支持，当前没有将任意 file URL 接入原生浏览器。

## 其他运行问题与后续优先级

- 画布 3、4 的普通追加输入最长分别延迟 399.802 秒和 608.472 秒。普通输入
  当前等待推理结束；本次期限提醒和显式加急可中断推理并保留工具执行。后续应
  将推理、排队及输入消费延迟分开显示，并对超时追加输入给出可操作的提示。
- 基线的两项同路径后台写入测试证明后完成的旧写入可以覆盖新写入。后续应按
  规范化路径序列化 write/edit，并为 bash 的共享写入明确任务顺序与成果版本。
  这项风险不能用“现有测试通过”说明已消除。
- 节点读取的 GIF 帧参数应与路径读取统一，或在发现阶段只提供支持的参数。
  本次已在工具说明和错误中明确 frame 仅用于路径图像；节点自动读取有效，动画验收继续依赖实际播放和原文件信息。
- 往后的产物交接可强制附带快照 hash、验证方式和交付状态，区分草稿、已提交
  与已验收成果。对于画布 3 的审查快照和最终快照，应明确版本变化，而不只复用标题。
