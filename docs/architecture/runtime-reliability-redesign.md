# 运行可靠性重构设计

状态：代码与本机受控验证已完成；真实模型和跨平台安装包验收见实施记录。设计基线为 v0.4.0，日期为 2026 年 10 月 14 日。

本次重构让原始任务在摘要压缩、模型限流、成员协作和阶段交付之后继续保持有效。依据见[我的画布运行复核](../development/m4-my-canvas-review-20261013.md)。实现采用一套新契约，不保留旧参数别名或两条运行链路；历史消息、文件和执行证据继续保留。

## 需要保持的行为

用户和有权委派工作的管理者决定任务目标。模型可以制定执行计划、报告进展和提出范围调整；摘要、工具结果、提醒和模型自己的计划不能生成用户授权。

任务完成、一次运行结束、消息已读、收到回复和工具成功分别保存。部分成果可以交付，但交付 partial 本身不结束仍然有效的任务。限流改变调度状态，不要求管理员重新发送原任务。

权限、暂停、停止、未知副作用和执行租约继续在服务端检查。改进恢复能力不扩大文件权限，也不自动重放已经执行或结果未知的操作。

## 模块边界

保持现有 PostgreSQL、授权服务、工具回执和文件快照设施，按变更原因拆出以下职责。

| 模块 | 负责 | 通过接口使用的能力 |
| --- | --- | --- |
| `modules/work/progress` | 真实指令引用、复核结论、交付关联和结束条件 | 现有消息、授权查询及运行调度 |
| `modules/context` | 上下文构造、摘要快照、来源校验和 checkpoint 选择 | 模型请求接口、上下文仓储 |
| `modules/model-runtime` | 模型请求排队、端点额度、租约、退避和请求诊断 | 提供者传输接口、调度仓储 |
| `modules/work/messaging` | 投递、回执、提醒及消息跟踪动作 | 现有通信授权、消息仓储 |
| `modules/execution` | 通用运行租约、工具准入、派发及效果回执 | 注册的处理器接口 |
| `adapters/model` | 提供者协议、流式响应、能力声明及错误解析 | 公共契约 |
| `adapters/host/files` | 文件定位、目录读取、流式文本、媒体和原子编辑 | 已授权的文件范围、固定执行入口 |
| HTTP 和 Web | 请求映射、状态展示和用户操作 | 公共契约及服务接口 |

依赖由上层运行编排指向下层能力。`execution` 不导入 `work` 或 `graph`；`context` 和 `model-runtime` 不读取画布业务表；任务和消息模块通过注入接口调用它们。模型适配器不决定重试任务，也不修改任务状态。HTTP 不直接访问数据库。

运行入口只编排“取得当前任务 → 处理输入及原工具回执 → 构造上下文 → 请求模型 → 持久保存结果 → 决定继续或等待”。摘要、额度、复核和文件操作都不继续追加到 `conversation-runtime/execute.ts`。

## 真实指令与统一进展复核

复用持久用户消息、获准委派原文、现有会话和运行记录。保存简洁的来源引用与处理边界，按接受顺序提供适用于当前成员的要求及后续修改。模型的摘要、计划和工具结果不能成为真实指令来源。此阶段不建立独立的 tasks、父子任务或计划管理系统，也不要求每条消息携带 taskId。

结束或等待前统一调用 `review_progress`。它直接检查当前信箱、相关交付、真实要求和执行状态；等待通过后直接进入等待，不再要求另调 `wait_for_message` 或携带模型侧确认 token。`review_inbox` 和 `wait_for_message` 不保留执行别名。

| outcome | 必需说明与引用 | 运行行为 |
| --- | --- | --- |
| `completed` | reason 对照真实要求说明交付和关键验证；需要产物或执行证据时提供 evidence_refs | 保存完成复核，关联 send_message 的实际交付，再允许最终答复与结束 |
| `continue` | reason、remaining_work | 当前任务仍有可推进工作，保持执行 |
| `waiting` | reason、remaining_work、dependency_ids | 依赖必须对应已有消息或唤醒条件；事务校验后直接等待 |
| `blocked` | reason、remaining_work，说明已完成部分和所需帮助 | 可见地结束本轮推进并保留阻碍，本轮结束不表示原要求完成 |

输入字段均在顶层，引用数组只包含字符串。例如：

```json
{"outcome":"waiting","reason":"实现已完成，需要等待测试结果","remaining_work":"检查测试结果并交付","dependency_ids":["msg_456"]}
{"outcome":"completed","reason":"要求的功能已实现，相关测试通过，成果已交付","evidence_refs":["artifact_123","test_run_456"]}
```

实际结果继续通过 send_message 交付，复核记录关联本轮已经提交或随后提交的结果，重复复核不重复发信。普通进度和确认收到不能证明委派工作完成；用户仅要求当前阶段时，完成该阶段即可。语义是否充分由模型结合验证证据判断，服务端校验来源、状态、授权及证据身份，不引入额外评审模型或例行人类批准。

自然结束未复核时由运行时 hook 提供具体待办和 review_progress 指引；同一输入状态下最多提醒两次。已有最终答复按生成时记录的输入边界及工具状态判断是否可复用，写入时间本身不能证明其使用了最新结果，审批恢复前的“等待中”答复不能替代恢复后的交付。用户取消、停止、预算耗尽、未知效果和运行异常有各自的运行时语义，复核不能覆盖它们或产生无限恢复。

## 上下文和摘要

每次模型请求更新系统规则和当前能力。近期真实输入保留在原生历史中的时间位置及工具配对关系；只有已经从保留历史中移除的真实指令，才按原顺序补充到历史之前。模型生成的摘要单独标记，新到达的输入在持久消费后进入下一次请求。不会为重申原目标而把所有新指令移到旧历史之前。

真实目标保留原文和来源，不依靠摘要重建。输入预算为它和当前权限、工具说明预留空间；无法容纳这些必要内容时返回明确阻塞，不静默截断有效指令。

当前模型上下文只包含一份有效摘要；上一有效 checkpoint 和历史摘要备份单独保留供恢复。摘要是带来源的历史背景。使用适配器支持的 assistant 历史上下文表示，并在可信提示中说明其来源和用途；不能把摘要或其中的“当前用户要求”生成新的 user 消息。近期原始 assistant/tool 配对及提供者不透明续接数据按适配器能力保留，不把可见思考文本替代原生续接协议。

摘要快照保存以下信息：

- 服务端确定的会话、源消息范围、源内容哈希、指令来源边界和模型请求 ID。
- 模型生成的事实、已作决定、已完成工作、未完成工作和证据引用。
- 校验结果、前一有效快照及提交时的上下文版本。

身份、范围、哈希和修订号由服务端生成，模型不能自报并覆盖。返回值必须满足结构要求，引用必须属于实际摘要范围，任务和工具状态由持久记录复核。一句行动承诺不能作为完整摘要提交。

结构校验不能证明自由文本全部正确，也不检测所有语义矛盾。因此任务目标始终独立保存；摘要中的完成、授权、停止和范围变化不直接产生状态变更。缺少必需字段、来源引用越界、输出截断或单句行动承诺时，拒绝候选摘要，保留上一个有效 checkpoint，并通过统一模型队列最多尝试三次。结构合法但内容错误的摘要仍是风险，需要真实模型复测，不能宣称已由格式校验解决。

摘要提交采用版本检查。生成期间到达的新指令先进入持久队列，下一次上下文构造必须使用新的真实指令边界；旧摘要最多覆盖其冻结的历史范围。取消、接管或旧 Worker 的迟到输出不能替换新 checkpoint。

保留摘要输出和精确来源清单，记录模型请求与响应标识、参数及工具集合哈希。默认诊断排除密钥和二进制正文；需要原始网络载荷的诊断模式独立授权、脱敏、限量和设置保留期。默认哈希记录不被描述为完整历史网络请求。

## 模型请求调度和恢复

Agent 运行容量和模型端点容量分别管理。14 名 Agent 可以同时有任务，但共享上游额度的模型请求需要排队。普通推理、上下文整理和其他生成请求使用同一个额度组。

额度组默认绑定端点配置；多个端点使用同一上游账户额度时，管理员可以将它们归入同一组。键只引用配置身份，不存储或传播明文凭据。模型窗口和请求类别可以细分限制，但不能把共享额度拆成互不知情的计数。

模型请求保存稳定的逻辑 ID、会话和运行 ID、上下文版本、用途、额度组、租约和每次网络尝试。请求状态为 `queued`、`leased`、`streaming`、`retry_wait`、`succeeded`、`failed`、`cancelled`。排队和退避不持有模型槽位。运行保持自己的租约与 Agent 运行并发额度，同时让出本地 Worker 工作槽；已派发工具保持原回执与所有者。

队列按会话公平调度，避免一个长会话或大量摘要占满槽位。摘要使用同一准入。首版不自动推测上游额度，不引入动态调参或复杂优先级。

| 错误类型 | 行为 | 给模型和界面的信息 |
| --- | --- | --- |
| 并发额度已满 | 保留原请求，等待额度并按分类退避 | 容量原因、队列状态、可得的限制值 |
| 引擎过载或临时速率限制 | 额度组统一冷却，有界退避及抖动 | 过载类别、下一次尝试时间 |
| 明确认证、配置失败或余额耗尽 | 阻塞相关请求，等待配置修正 | 安全的配置入口和错误类别 |
| 超时或临时网络错误 | 在提交与副作用规则允许时恢复请求 | 失败阶段、尝试次数和恢复条件 |
| 不明确的已派发副作用 | 保留原调用并阻塞自动重放 | 待核实的执行身份及允许操作 |

优先遵守有效 `Retry-After`。初始调度默认值采用每额度组 4 个请求、退避从 1 秒增加至 60 秒并加入抖动、自动重试窗口 10 分钟。窗口从首次故障或共享冷却开始，普通容量排队不消耗故障恢复预算；准入事务在派发前检查期限。超过窗口或上游要求更久等待时，显示明确失败和最早可尝试时间，不提前请求。工作及回执保留，继续时使用当前合法上下文。

应用层不能保证控制其他应用对同一上游账户的占用。429 可用于降低本地压力，不能仅根据错误文本提高本地上限。取消后按传输结束证据或租约规则释放槽位，避免供应商尚在生成而本地立即重复占用。

移除分散的请求重试包装，重试由这一层统一决定。一次提供者请求不能被适配器、摘要器和运行器各自重试。上下文已提交或工具已派发时，后继请求使用最新合法历史，不能重放旧请求中的操作。

`get_agent_status`、运行通知、UI 和诊断共用安全的请求状态投影，包括请求 ID、状态、错误码、尝试次数和下一次尝试时间。运行时根据错误分类决定是否重试；额度组共享冷却，普通重试不会反复唤醒所有管理者。

## 消息提醒和信箱复核

消息分别保存已读与回复义务，进展复核关联本轮交付结论。确认收到消息可以结束“等待回复”，但不会自动完成关联任务。发送阶段结果和最终结果都使用已有来源与回复关系，减少“先向 manager 报告，再另发一条回复关闭原消息”的重复操作。

普通超时提醒只表达待跟进事实。运行者在安全边界处理；空闲或等待者可以按现有授权和预算被唤醒。明确的停止、真实权限撤销及显式加急使用各自的中断路径。系统不会仅因普通提醒到期就设置 expedited。

提醒按发送者和事项聚合，分别保留未读和回复截止时间。重复提醒采用可配置冷却，新提醒可以更新待处理组；已经被处理或已经失效的条件不反复投递。显式加急仍检查接收者权限、暂停状态和冷却，并引用原消息身份。

复核分为“阅读当前消息”和“处理尚未结束的责任”。服务端将普通已完成回执移出待决集合，保留历史记录。每个待决项有独立修订，整个信箱另有新增输入序号，避免把回执完成与新责任到达当成同一种变化。

`read_inbox` 提供稳定分页、短引用和增量信息，当前信箱状态由服务端读取，不要求模型提交历史副本。短引用绑定会话与消息身份，分页游标冻结该次读取的排序；每次操作重新检查真实消息、责任与权限。

逐条责任通过独立的扁平 `update_message` 处理，例如：

```json
{"delivery_id":"msg_123","action":"background","reason":"结果不影响当前交付，收到后再跟进"}
```

普通信息随实际上下文消费保存读取进度。未回复请求、依赖等待、成员退出及取消责任仍须有明确处理。不存在 `decisions`/`messageDecisions` 对象数组，也不要求复制所有普通消息 ID。重复提交返回原回执；未处理项以具体 ID、短引用及允许动作返回。

| 复核期间的变化 | 处理 |
| --- | --- |
| 对方读完无需回复的消息 | 自动移除已解决项，保留其余决定 |
| 收到预期回复 | 关闭原等待项，把回复作为新输入供检查 |
| 新指令、新请求或成员退出 | 只使相关决定失效，检查新责任 |
| 权限、归属或处理责任变化 | 重校验受影响项，保留无关进度 |
| 仅提醒时间或显示状态更新 | 不要求重新确认全部历史 |

`review_progress` 在同一事务内重新检查输入边界、必需消息、相关决定、证据权限及运行租约，直接保存继续、等待、阻塞或完成复核。内部版本检查不暴露成模型必须传回的最终 token。允许结束与实际最终交付分别记录，保持一次交付身份。

## 文件读取契约

`read` 使用扁平的目标字段。首次读取在 `path`、`nodeId`、`skillId` 中恰选一个；继续读取只提交 `cursor`，目标、模式和位置由游标绑定。

```json
{"path":"/workspace/census.json","mode":"text"}
{"nodeId":"published-node-id","page":1}
{"skillId":"catalog-skill-id"}
{"cursor":"read-cursor-token"}
```

保留按行、PDF 页和图片帧定位的初次读取，定位字段位于顶层。模式默认 auto；目录接受 auto/text 并返回目录条目。目录使用图像或行定位参数时给出最小合法调用。各目标继续分别检查文件、节点和技能授权，游标不提供额外权限。

文本读取采用有界流式解码。初始每次返回上限为 32KiB 文本和 200 行，单次定位扫描上限为 1MiB，并设置执行时间上限；不再以整个文件是否超过 1MiB 决定能否分页。跨页维护 UTF-8 边界、行号、字节位置和超长行续读位置。

定位较远行号时使用有界扫描和可恢复位置，达到本次扫描预算时返回 `positioning` 状态与下一游标，不能把尚未读到的位置报告为 EOF。当前通过游标继续扫描，不额外维护文件行号索引。

短游标对应服务端的读取会话，持久绑定画布、会话、目标、模式、位置和来源版本，有效期为 1 小时，每会话最多保留 128 个。重启后仍可在期限内继续；过期返回重新打开的明确指引。每页都重新检查当前授权。

节点文件绑定不可变快照哈希。可变路径通过安全打开、物理身份及读取前后的文件元数据检测变化；变化后返回 `SOURCE_CHANGED`。元数据一致不被描述为完整文件的密码学证明，需要固定字节验收时先使用发布快照。替换文件、符号链接、撤权和跨画布游标不能绕过权限。

文件定位、流式文本、目录、PDF、图片和原子编辑分别放入独立模块。固定 Host 执行入口只接受类型化操作，不再把所有文件逻辑堆在一段内嵌脚本中；调用入口继续服从实际沙箱和权限配置。

## 工具结果和错误

移除含义不清的 `executed` 布尔值，统一表达调用状态、失败阶段和效果状态。对模型决定是否重试最重要的是效果是否发生及结果是否确定。

```json
{
  "call":{"callId":"call-id","state":"rejected","phase":"validate","effect":"none"},
  "error":{
    "code":"READ_CURSOR_INPUT",
    "path":"/cursor",
    "message":"Continue with only {cursor} / 续读只传 {cursor}"
  }
}
```

状态使用 `rejected`、`queued`、`running`、`succeeded`、`failed`、`unknown`；阶段使用 `validate`、`authorize`、`dispatch`、`execute`、`commit`；效果使用 `none`、`committed`、`partial`、`unknown`。状态与效果不互相替代：命令启动后失败可能已经改变文件；成功读取没有持久写入效果。

参数或编辑匹配校验失败返回 rejected/none。授权尚未满足返回排队或等待原因。已经提交的效果优先使用持久回执，不能被迟到异常改成“未执行”；无法确认的外部操作保留 unknown 并阻止自动重放。部分成功必须报告受影响的操作或产物范围。

参数错误提供字段路径、预期类型或约束和修正动作，必要时附符合当前角色的示例；不回显提交的正文或密钥。当前新增运行时错误提供中英说明，UI 按界面语言呈现状态。提供者错误先分类再投影，原始错误正文不进入模型请求状态。

## 提示词和界面

系统规则、工具参数、任务状态和可执行动作来自同一个当前能力快照。新请求、恢复、降权、摘要后和配置变更后都重新构造。read/write/admin/owner 的中英文版本使用同一状态定义，保留当前权限和原任务来源。

提示词明确区分：阶段交付后继续原任务；模型额度不足时等待调度；协作依赖未解决时等待消息；未知执行结果先核实。提示词要求模型遵守这些边界；是否正确理解任务和摘要仍须通过真实模型验证。

UI 展示模型排队、重试倒计时、进展复核未完成和任务阻塞提示。调度时间表示下一次尝试，不能当作完成时间。错误码及调用身份用于诊断，普通状态不显示内部额度组 ID。

协作气泡沿用已读、未读和加急图标及现有位置，保留悬浮时间和滚动后的身份栏。普通提醒不使用加急样式。额度组统一冷却，单次重试不反复发送失败通知；各运行最终失败仍保留自己的记录。复核结论与当前运行状态分别存储，不把“本轮结束”显示成完整任务完成。

实施阶段、文件拆分约束、数据切换和验收矩阵见[运行可靠性实施计划](../development/runtime-reliability-implementation.md)。
