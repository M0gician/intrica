# 上下文压缩实验与实现

日期：2026-10-15。基线：v0.5.3 / `95240c5`。采用完整旧摘要、轻量文本交接、独立当前状态和按需查询原始来源的组合。原生压缩和后台压缩没有在本轮启用。

## 问题与候选

此前本地画布的只读复核发现，35 次摘要衔接中有 29 次旧摘要被普通文本首尾截断；最严重一次省略中间 8,075 字符，包括 4 条完整已完成事项及 4 条待办。另有 3 次摘要连续校验失败，但当时未保存拒绝输出，无法确定具体拒绝原因。本轮只使用脱敏合成资料和隔离数据库，不改动正在运行的画布。

| 候选 | 摘要输入与输出 | 当前状态与证据 |
| --- | --- | --- |
| A，冻结基线 | 普通文本首尾各 3,000 字符；固定四数组 JSON | 原有摘要与近期内容 |
| B | 旧摘要完整输入；有界文本交接 | 其他条件与 A 一致 |
| C | 与 B 相同 | 责任独立保存，原始来源按版本检索和分页读取 |

三条路线并行验证。生产实现采用 B 的摘要修复和 C 的状态与证据设计；没有将模拟抽取器当作生产摘要器。

## 连续压缩机制实验

两种语言分别执行 30 轮，当前窗口总预算均为 6,000 字符，计入摘要、责任及索引。摘要由确定性抽取器生成，验证的是可见性、预算和可恢复性，不能证明真实模型理解能力。三条路线都保留原始记录；下表遗漏指窗口内缺失。

| 语言/指标 | A | B | C |
| --- | --- | --- | --- |
| 中文当前责任 | 29/41 | 37/41 | 41/41 |
| 中文窗口内历史事实 | 35/51 | 40/51 | 48/51 |
| 英文当前责任 | 24/41 | 24/41 | 41/41 |
| 英文窗口内历史事实 | 21/51 | 22/51 | 29/51 |

C 中文通过额外读取 3 页、1,536 字符恢复 51/51；英文需要 22 页、11,264 字符。召回成本单独计量，结果不表示所有事实都应常驻窗口。两项原始任务约束在所有候选中均保留。单个 900,041 字符工具结果实验确认：调用和结果保持完整配对；中段证据可以按引用读取，有限预览无法独自保留它。


## 真实模型对照

使用当前配置模型，协议为 `openai-completions`，模型指纹 `3c51a0b181f2`。2 个合成任务 × 3 条路线 × 摘要及接续各 1 次，共 12 个请求，并发 2、每请求输出上限 2,000 tokens，无自动重试。每项检查 6 个明确字段：审批要求、任务完成状态、阅读位置、待回复报告、缓存 TTL、失败用例。

| 案例 | A | B | C | C 额外召回 |
| --- | --- | --- | --- | --- |
| 长旧摘要，中段包含关键事实 | 2/6 | 6/6 | 6/6 | 1 次搜索、2 页、1,024 字符 |
| 大工具结果，中段包含关键事实 | 2/6¹ | 2/6 | 6/6 | 1 次搜索、1 页、512 字符 |

¹ A 的大工具案例摘要以 `length` 结束，候选拒绝，2/6 来自原有效检查点的回退结果。不能把它计作新摘要安装成功。

C 在这一组由程序按题目主题选择检索，不是模型自主调用工具。一个模型、每路线每题仅一个样本，不能据此宣称统计优势、长期交付率或所有模型上的效果。完整旧摘要只解决来源裁剪，独立状态和证据恢复解决另一类问题。各请求 token、耗时、结束原因与逐字段分数见[脱敏结果](context-live-2026-10-15.json)。

```sh

# 配置由操作者显式提供，不提交配置文件。
node scripts/context-experiments/live.mjs --live --config-file /private/model.json --out /tmp/context-live.json
```

## 自主召回迭代

使用隔离 PostgreSQL 与生产归档、`invokeTool/read_context`，仅向模型提供该工具。模型自行选择关键词、引用与位置。两轮各最多 6 个请求、每次最多 2,000 输出 tokens、无重试；同一合成任务，未注入程序预选证据或额外标准答案状态。

| 指标 | 首轮：整句子串查询 | 迭代：多关键词及直接命中引用 |
| --- | --- | --- |
| 核对结果 | 0/6，未形成最终答案 | 5/6，返回完整答案 |
| 模型请求 / 工具调用 | 6 / 11 | 6 / 5 |
| 输入 / 输出 tokens | 14,094 / 2,071 | 14,414 / 1,526 |
| 工具响应字符 | 11,696 | 8,190 |

首轮模型自然使用多个关键词，整句匹配得到空结果，随后消耗轮次在目录跳转和从头读取，最终触及实验的工具批量护栏。生产搜索据此改为按空格分词、任一字面子串匹配、优先多词命中，并返回直接来源引用和命中位置；同时补齐当前摘要搜索。

第二轮在第二次请求中自主定位并跳读中段，正确恢复 5 项档案事实。剩余 `approvalRequired` 返回 null，未把原始用户要求“未经批准不得修改数据”解释为 true；这属于剩余指令解释问题，不能以召回成功掩盖。该小样本不证明统计优势，输入 token 也未下降。详细记录见 [v1](context-autonomous-v1-2026-10-15.json) 与 [v2](context-autonomous-v2-2026-10-15.json)。

```sh

node scripts/context-experiments/autonomous.mjs --live --config-file /private/model.json --out /tmp/context-autonomous.json
```


## 实现范围

- `modules/context` 保留完整旧摘要；仅缩短模型看到的普通工具预览，完整可读文本进入归档。近期交互按完整调用组保留，预算为窗口的 10%，最多 20,000 tokens。原始要求继续独立保护。摘要正文最多 24,000 字符。格式与措辞不承担语义有效性判断；传输完整性、长度和工具调用仍由服务端校验。
- `model-runtime` 是唯一网络重试入口。空响应、截断、过长或工具调用返回具体诊断，最多一次带反馈修正；修正次数与验收记录持久化，工作进程重建不会重置额度。服务重启的传输中断保留请求与修正预算；用户主动取消保持终态，尚可能占用的提供者并发槽保留到租约到期。记录输出哈希、最多 16,000 字符审计摘录及验收元数据，普通 trace 不返回正文或 thinking。
- `conversation-runtime` 每轮从业务记录重建当前消息责任、待执行工具、最近复核与阅读进度。当前状态有界注入，完整消息通过 `read_inbox` 查询；摘要无法关闭责任或改变权限。摘要、来源和 checkpoint 在同一事务、同一运行 epoch 下提交。
- 压缩失败保留原检查点与已执行回执，进入 `waiting/context_blocked`。自动消息不能恢复这类暂停；用户明确继续后创建新运行和新的有界模型请求，采用新选择的模型配置。暂停前停止后台执行，已确认结果保留，无法确认的外部效果标记 unknown；核实前阻止新运行，避免重复效果。
- `work/context-library` 复用压缩版本保存可读来源，不为每次压缩创建画布节点。`read_context` 提供目录、概览、全文检索和原文分页。Agent 仅查询自身会话，读取时核验归档权限范围；UI 在详情页提供折叠“工作资料”，按需载入，中英文一致。
- `read` 用于首次定位，`read_next({cursor})` 用于续读。实际成功回执生成独立阅读记录，保存源版本、已返回范围和继续位置；记录表示工具已返回内容，不能当作模型已理解全文的证明。已过期游标提供重新定位依据，读取仍检查版本及当前权限。
- schema 升至 18，工具协议升至 7。旧的未派发调用被封存并要求重新规划；已执行回执保留。已失效的“压缩前保存笔记”开关删除，归档成为压缩事务的一部分。

核心新增模块按来源处理、归档、权限、投影、搜索、阅读观测、工作状态与错误恢复拆分。API、工具参数、模型提示词和 UI 同步更新。

## 验证与边界

生产回归覆盖 30 轮压缩后按原引用恢复各轮中段证据，长旧摘要经真实 HTTP transport 的完整输入，摘要/原文分页哈希，跨会话拒绝、归档后撤权、派生摘要权限继承、取消与 epoch 变化、持久化修正预算、显式继续以及已完成工具回执保留。

受控故障夹具比较 4 类无效响应：旧原样重放共 12 次调用、0/4 修复；新定向反馈共 8 次调用、4/4 修复，并保留指定事实。夹具第二次按反馈返回有效文本，因此该数字验证恢复协议，不是提供者真实修正率。

本轮没有实现或验证：原生提供者压缩、后台候选提交、压缩失败后的自动恢复上下文构造、语义向量检索、3 人/14 人真实团队长期交付率和安装包发版。全文检索使用词法匹配。当前状态提供最近阅读位置，完整阅读记录不等于覆盖或理解认证。

权限声明限定于新增资料索引：按归档时记录及继承的范围，在读取时重检。既有 `read_conversation`、`get_tool_result` 与 checkpoint 在历史授权撤销后的全链路重建不属于本轮全面解决范围。对已经缺损的旧摘要，本次更新保留审计记录，不自动补写或重新执行历史操作。

## 实现清理与消融复核（基线 `ecf85a2`）

清理来源处理中的重复调用：来源选择与哈希只执行一次，随后生成稳定引用和模型预览；摘要输入与归档共用可读文本投影。移除压缩前无用的图片加载、未使用的 Agent session 参数、重复非空检查，以及仅供测试调用的摘要解析包装函数。

摘要的模板版本、提示词、长度上限和校验归并到 `summary-contract.ts`。删除按 `I will` / `我会` 开头判断摘要无效的规则，以及对正文的额外 JSON 包装协议。服务端标记确定哪些消息是生成摘要，用户引用旧摘要标题也会完整保留。模板版本升为 v2，避免复用旧模板的模型请求身份。

HTTP 与 `read_context` 共用一份查询 schema；字段类型和范围在入口校验，原文长度与 Unicode 位置在读取时检查。阅读状态查询固定取最近 8 个来源，明确传入当前授权检查所需的 host；删除可选 host、任意 limit 及无 host 的查询回退。停止后台执行的回调改为必填。读取授权时仅把预期的撤权或文件不可访问错误转换为空结果，数据库和代码错误正常上报。

| 对照 / 消融 | 结果 |
| --- | --- |
| 清理前后 30 组上下文 | 原文、来源哈希、引用、近期消息与归档投影一致 |
| 3 个有效的中英文及结构化交接文本 | 原规则全部误拒；清理后全部保留原文 |
| 来源整理微基准 | 同进程交替顺序、2 次预热及 7 次测量，30 组输入的中位耗时约 11.2 → 5.6 ms；计时范围仅含本地来源整理 |
| 截短归档原文、跳过归档授权、移除候选预算检查 | 3 项生产集成测试均检出错误 |
| 忽略未确认外部效果、取消分页入口范围校验 | 2 项生产集成测试均检出错误 |

移除两类重复测试：只对内存 Map / 自建抽取器作断言的测试，以及在生产纠错回归外重复运行旧三次重试比较的测试。故障恢复测试直接调用生产摘要校验器，去掉自建 validator。研究用 Map 移除伪造的权限层和未使用接口，历史实验输出保持不变。原始 A/B/C 研究脚本和历史结果保留用于复现；当前 CI 只额外检查真实模型 runner 默认不读取凭据、不发起付费请求。30 轮真实传输和生产压缩、事务、权限、取消、重启及工具效果回归继续保留。
